# 🎯 How Frontend Build Works with Different Domains

## Your Question

> "We are creating frontend build on localhost... how is it working online? Is installer replacing anything frontend URL?"

## ✅ The Answer

Yes! The installer **DOES** configure the frontend to work with your online domain. Here's exactly how it works:

---

## 🔧 The Solution: Runtime Configuration

### **Problem:**
When you build the frontend with `npm run build`, it creates static files (HTML, CSS, JS). Normally, the API URL would be hardcoded into these files during build, making it impossible to change later.

### **Solution:**
We use **Runtime Configuration** - the API URL is loaded dynamically when the page loads, not during build time.

---

## 📋 How It Works (Step by Step)

### **Step 1: Build Locally**
```bash
npm run build
```
- Creates `build/` folder with HTML, CSS, JS files
- The code is **generic** - it doesn't have a hardcoded API URL
- Instead, it looks for a runtime config file

### **Step 2: Package for Deployment**
```bash
./create-deployment-package.sh
```
- Creates `billingtool.zip` containing:
  - Built frontend files
  - API backend
  - Database schema
  - A template `config.js` file

### **Step 3: Installer Generates Config**
When you run `installer.php`:
```php
// Installer creates config.js with YOUR domain
$configJs = "window.APP_CONFIG = {
  API_BASE_URL: '{$this->config['api_url']}/index.php'
};";

file_put_contents(EXTRACT_PATH . '/config.js', $configJs);
```

### **Step 4: Frontend Loads Config**
```html
<!-- index.html -->
<script src="/config.js"></script>  <!-- Loads first -->
<script src="/app.js"></script>      <!-- Then loads app -->
```

### **Step 5: App Uses Runtime Config**
```typescript
// src/utils/config.ts
export const getApiBaseUrl = (): string => {
  // Priority 1: Runtime config (set by installer)
  if (window.APP_CONFIG?.API_BASE_URL) {
    return window.APP_CONFIG.API_BASE_URL;  // ← Uses installer's URL
  }
  
  // Priority 2: Development fallback
  return 'http://localhost:8080';
};
```

## 🎯 Example Flow

### **Development (localhost):**
```
1. You run: npm run dev
2. Vite uses: http://localhost:8080
3. App works locally ✅
```

### **Production (yourdomain.com):**
```
1. You build: npm run build
2. You package: ./create-deployment-package.sh
3. You upload: billingtool.zip + installer.php
4. Installer creates: config.js with https://yourdomain.com/api/public/index.php
5. Browser loads: config.js first
6. App uses: https://yourdomain.com/api/public/index.php ✅
```

## 📁 Files Involved

### **1. `public/config.js`** (Template)
```javascript
// This is just a template in the source code
window.APP_CONFIG = {
  API_BASE_URL: 'http://localhost:8080'
};
```

### **2. `installer.php`** (Generates Real Config)
```php
private function createConfigFile() {
    $configJs = <<<JS
// Generated by installer
window.APP_CONFIG = {
  API_BASE_URL: '{$this->config['api_url']}/index.php'
};
JS;
    
    file_put_contents(EXTRACT_PATH . '/config.js', $configJs);
}
```

### **3. `src/utils/config.ts`** (Uses Config)
```typescript
export const getApiBaseUrl = (): string => {
  // Reads window.APP_CONFIG set by config.js
  if (window.APP_CONFIG?.API_BASE_URL) {
    return window.APP_CONFIG.API_BASE_URL;
  }
  return 'http://localhost:8080'; // fallback
};
```

### **4. `src/services/api.ts`** (API Client)
```typescript
import { getApiBaseUrl } from '../utils/config';

const API_URL = getApiBaseUrl(); // ← Gets URL from runtime config

const api = axios.create({
    baseURL: API_URL  // ← Uses the correct URL for your domain
});
```

## ✅ Benefits of This Approach

1. **Build Once, Deploy Anywhere**
   - Same build works on any domain
   - No need to rebuild for different environments

2. **Easy Configuration**
   - Installer handles everything
   - Just fill in the form with your domain

3. **No Hardcoded URLs**
   - API URL is not baked into JavaScript
   - Can be changed without rebuilding

4. **Works Offline and Online**
   - Development: Uses localhost
   - Production: Uses your domain
   - Automatically detects which to use

## 🎯 Summary

**Question:** How does a build created on localhost work on a different domain?

**Answer:** 
1. The build is **generic** - no hardcoded URLs
2. The installer **generates a config.js** file with your domain
3. The app **reads this config** at runtime
4. All API calls use **your domain's URL**

**Result:** ✅ Same build works everywhere!

---

## 📝 Technical Details

### **Priority Order for API URL:**

```typescript
1. window.APP_CONFIG.API_BASE_URL  // Set by installer (PRODUCTION)
   ↓ (if not found)
2. import.meta.env.VITE_API_BASE_URL  // Set during build (DEVELOPMENT)
   ↓ (if not found)
3. 'http://localhost:8080'  // Hardcoded fallback
```

### **Why This Works:**

- **Development:** No `config.js` exists, uses environment variable or fallback
- **Production:** Installer creates `config.js`, takes priority over everything
