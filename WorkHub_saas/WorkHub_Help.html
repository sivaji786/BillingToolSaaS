WorkHub — User Help

WorkHub is the field work management module of the SCLAN 5.0 platform. It covers task assignment, time recording, material logging, customer acknowledgment, and invoice preparation — fully language-agnostic and legally compliant across EU jurisdictions.

Overview

WorkHub connects field technicians, planners, managers, clients, and finance in a single application. Every piece of data entered by one role is immediately visible to all other roles in their own language.

RolePrimary useKey views
WorkerExecute tasks on siteToday, Timesheet, Profile
PlannerAssign and schedule workAll records, New task
ManagerOverview and capacityKanban, Workload
ClientTrack project progressProjects, Deliverables
FinanceInvoice preparationTime & Finance, Invoice lines

Roles

Switch roles using the role selector in the desktop topbar. The same data is shown through different lenses depending on the selected role. On mobile, the Worker view is the primary interface.

Role switching
Switching roles does not change your identity or permissions — it changes which views and actions are shown. In production, roles will be assigned per user account.

Mobile interface

The mobile interface is designed for field workers using a phone on site. All controls are reachable with one thumb. No hover states are used anywhere — all interactions are taps.

Task cards

Each task card shows the project name (colour-coded), task title, client name, status badge, priority, and estimated vs logged hours. If there are other open tasks for the same client, a small +2 on site badge appears on the client line.

The timer bar at the bottom of each card shows the elapsed time for the current session. Tap ▶ Start to begin recording. ☕ Break pauses the timer without ending the session. ⏹ Stop ends the session, writes the time entry, and opens the Done report.

Desktop interface

The desktop layout uses a three-panel structure: left sidebar (navigation + project list), main panel (varies by role and view), and right panel (quick actions and export).

The language dropdown and role selector are in the topbar. The sidebar shows the current worker's queue depth below their name — colour-coded green/amber/red by utilisation.

Tasks

Tasks are the central work unit. Each task belongs to a project and client, has a status, priority, estimate, and assignee.

Task actions

Three action buttons appear at the bottom of each task card:

  • ✅ Done — opens the completion report flow
  • ⚠️ Problem — opens a problem report

Timer & timesheet

WorkHub records working time automatically when you use the timer. This satisfies the legal requirement for systematic working time recording under § 16 ArbZG and the EuGH ruling C-55/18 (2019).

Start timer
Tap ▶ Start on any task card. The dot turns green and blinks. The counter starts. Task status changes to In progress automatically.
Take a break
Tap ☕ Break to pause. Elapsed time is preserved. The session continues without creating a separate entry yet.
Stop timer
Tap ⏹ Stop. A time entry is written with: task ID, worker, start time, end time, duration, and type. The Done report opens automatically for customer acknowledgment.
Review timesheet
Open the ⏱ Timesheet tab. See today's total, all sessions grouped by task, break entries, and running total. Sign off at the bottom.
Legal compliance — § 16 ArbZG

Records are kept for a minimum of 2 years. Digital sign-off counts as legal signature under § 127 BGB. If daily logged time exceeds 8 hours, the system warns: "30 min break required by law." Records are available for employer inspection on demand.

Done reports

When a task is completed, the worker submits a Done report. This record is the official confirmation of delivery and the basis for invoicing.

Completion flow

Write completion note
Describe what was done. Write in any language — the system will translate automatically for other users.
AI correction review
If the text has spelling, grammar, or language errors, the AI suggests a corrected version. You see your original and the correction side by side. Tap ✓ Yes, use this to accept, or ✗ Keep mine to store as written. Your original is always preserved and accessible via "show original".
Overrun reason (automatic)
If logged time exceeds the estimate, a yellow box appears asking for the reason. This is also AI-corrected before storing.
Photos
Take photos with the camera or upload from the gallery. Multiple photos supported. Photos appear as thumbnails and are included in the invoice record.
Materials
Add any materials used: name, quantity, unit, unit price, and a bill comment that appears on the invoice. A running total is shown.
Customer acknowledgment
The customer reads the data protection notice, signs, provides their name, and optionally provides an email to receive a copy.
Teaching through correction
The AI correction step is not just quality control — it teaches correct phrasing. A worker who consistently sees their broken German corrected to professional German will naturally learn the correct forms over time. Original text is always preserved for reference.

Customer signature & identity

The customer acknowledgment block is shown at the end of every Done report. It contains four elements:

1. Full name (required)

The customer's printed name. Required field. As the name is typed, the acknowledgment statement at the bottom updates live to personalise it: "Herr Schmidt confirms the above work has been completed to satisfaction…"

2. Role / company (optional)

The customer's role and company — e.g. Hotel Manager · Hotel Mitte GmbH. Stored separately and shown on the invoice below the signature.

3. Handwritten signature

A touch-and-stylus signature canvas. The customer signs with their finger on the phone screen. Works with any stylus. Tap Clear to start over. Status shows unsigned until strokes are detected, then ✓ signed.

4. Identity photos

Optional but recommended for high-value jobs or disputed completions. Two options:

  • Take photo — opens the rear camera. Photograph the person, their ID card, employee badge, or any physical proof of identity.
  • Upload / QR — opens the file picker. Use for QR code stickers, barcode scans, saved ID documents, or any image from the device gallery.

Multiple identity photos per acknowledgment. All are stored with the completion record and shown in the invoice.

Data protection notice

A collapsible 🔒 Your data is protected panel appears above the signature area. The customer taps to expand it and reads a plain-language explanation of:

  • What is collected and why (delivery confirmation only)
  • Legal basis (GDPR Art. 6(1)(b) — contractual necessity)
  • Storage (EU servers, encrypted, 10-year retention, never sold)
  • Their rights (Art. 15–22: access, correction, erasure, portability, objection)
  • Standards complied with (see Legal & Compliance section)

Paper signature alternative

If the customer refuses to sign on screen — for any reason — the worker can print the consent form instead:

  • 🖨 Print consent form — prints a full A4 document with the legal notice, acknowledgment statement, and signature/name/date/contact fields. The customer signs with a pen.
  • Photo of signed form — after the customer signs on paper, the worker photographs the signed document using the rear camera and uploads it. This is stored in the completion record as paperSignaturePhoto alongside any digital signature.

The printed form includes a reference number and a note for the worker reminding them to photograph and upload it via the app.

Send me a copy — multi-channel

A toggle at the bottom of the acknowledgment block enables the copy delivery option. The customer chooses their preferred channel:

A Polish worker can use the app in Polish, write notes in Polish, and generate a German-language invoice for a German client — all at the same time. The three settings are completely independent.

Content translation

All user-entered content — task titles, descriptions, completion notes, materials — is automatically translated to each user's selected language. There are no translate buttons. There are no language badges. The system handles it silently.

How it works

Content renders
When a task card, detail panel, or invoice line renders, every text field is passed through autoTr(text).
Cache check
The system checks the translation cache keyed by hash(text)::targetLang. If found, the translated text is returned instantly.
Async fetch
If not cached, the original text renders at reduced opacity while the Anthropic API translates it in the background. When complete, the text updates in place.
Cache stored
The translation is cached permanently for the session. Same text is never translated twice. Switching language clears the cache so content re-translates to the new language.

Parallel deduplication

If multiple components request the same translation simultaneously, only one API call is made. All waiting components receive the result when it arrives. This prevents duplicate API calls when re-rendering.

Fallback behaviour

If the API call fails, the system checks the cache for the same text in the fallback language. If a fallback translation is cached from a previous successful call, it is shown. Otherwise the original text is displayed unchanged.

AI text correction

When a worker submits a completion note, delay reason, or any free-text field, the AI checks it for spelling errors, grammar problems, and incorrect language before storing.

The correction review flow

If the AI changes anything, the modal does not close. Instead, a review panel appears showing the original text and the corrected version side by side:

✎ Text corrected — ok like this?
You wrote:
Ich habe gemacht installation von zone B, es war schwierig weil kabel kurz
Corrected to:
Installation Zone B abgeschlossen. Verkabelung war aufwändig, da Kabellänge nicht ausreichte.
✓ Yes, use this
✗ Keep mine

Worker choice

  • ✓ Yes, use this — corrected text is stored. Original is preserved in the record as completionNoteOriginal. Anywhere the note is displayed, a small ✎ show original link appears.
  • ✗ Keep mine — original text is stored unchanged. No correction flag is set.

Cross-language correction

The AI detects the language the worker actually wrote in — even if it is broken or mixed — and corrects it to the current UI language. A Polish worker writing poor German will have their text corrected to professional German. The correction prompt instructs the AI to:

  • Detect what language was written (even if broken/mixed)
  • Fix all spelling, grammar, and awkward phrasing
  • Write it properly in the UI language
  • Keep it concise and professional — work note style
  • Preserve names, product codes, numbers, measurements, and dates
Language learning mechanism
By seeing the corrected version before accepting it, workers gradually learn correct professional phrasing in the target language. This is a deliberate teaching mechanism embedded in daily work. Over months of use, workers who write in a foreign language improve measurably.

Show original

When a correction was accepted, a ✎ show original link appears wherever the note is displayed — in the invoice, in the task detail, in the completion history. Tapping it shows the original text in an amber-bordered box. Tapping again hides it. The original is never altered and never lost.

Creating tasks

New tasks are created via the + button in the mobile header or the + New task button in the desktop topbar. The flow has two steps.

Step 1 — Task basics

Title (required), description (optional), priority (High / Medium / Low), due date, estimated hours. The Next button is disabled until a title is entered.

Step 2 — Project, customer, and worker

Assign to an existing project by tapping its chip, or create a new project by tapping + New project. New projects require a customer — choose from existing customers or tap + New customer to create one.

The worker assignment section shows capacity cards for all workers (see Capacity planning). Tap a card to assign.

Capacity planning

WorkHub calculates each worker's workload and queue depth in real time from all open assigned tasks.

  • "2 weeks ahead" — 1–4 weeks of work queued
  • "3 months ahead" — significant backlog

Impact preview

When assigning a new task, if an estimate has been entered, each worker card shows an after preview — the queue depth after adding this task. A warning appears if adding the task would overload the worker this week.

Colour coding

  • Green — under 70% capacity
  • Amber — 70–90% capacity
  • Red — over 90% — overloaded

On-site context

When a worker opens a task detail, WorkHub shows all other open tasks for the same client and project. This allows efficient batching of work at the same location.

The section is titled "Also at this location" and lists tasks with their title, project colour, due date, estimate, priority, and a ▶ Start button. Tapping Start begins the timer for that task without navigating away.

Task cards also show a small +2 on site badge on the client line when other tasks exist for that client.

Working time law

§ 16 ArbZG — Arbeitszeitgesetz (Germany)

Employers must record all working hours systematically. WorkHub generates this record automatically from timer sessions. Records include start time, end time, and duration per session. Break entries are recorded separately. Sign-off is digital.

EuGH C-55/18 (2019) — ECJ ruling

The European Court of Justice ruled that all member states must require employers to set up an objective, reliable, and accessible system for measuring daily working time. WorkHub's timer system satisfies this requirement.

Retention

Time records are retained for a minimum of 2 years in accordance with § 16 ArbZG. This is enforced at the data layer.

Break warnings

When a worker's logged time for the day exceeds 8 hours, the timesheet view displays: "⚠ 30 min break required by law" in accordance with § 4 ArbZG.

Customer rights

Every customer who signs a completion acknowledgment is informed of their GDPR rights in plain language before signing:

  • Access (Art. 15) — request a copy of stored data
  • Correction (Art. 16) — have inaccurate data corrected
  • Erasure (Art. 17) — request deletion where not overridden by retention law
  • Portability (Art. 20) — receive data in machine-readable format
  • Objection (Art. 21) — object to processing at any time

Electronic signature

The customer handwritten signature captured on the device screen constitutes a simple electronic signature under eIDAS (EU) 910/2014, Article 3(10). This is legally valid for service delivery confirmations across all EU member states.

What makes it legally valid

  • Biometric uniqueness — the drawn signature is unique to the individual
  • Name confirmation — the printed name field confirms identity
  • Timestamp — ISO 8601 timestamp is stored with the signature
  • Context — the acknowledgment statement records exactly what was signed
  • Identity photos — optional additional identity confirmation (ID card, badge, QR code)
  • Audit trail — full record of who created, modified, and accessed the completion record

Storage

Signatures are stored as PNG images (base64-encoded). The stored record includes: signature image, name, role/company, identity photos, and the exact timestamp of signing. This record is immutable once stored.

PPT — Project Planning Tool

PPT is the future SCLAN SaaS module for project planning. It works with WorkHub and PFE to give planners and managers multiple views onto the same project reality — without any double-entry or synchronisation problems.

The key idea

A task is a task. Whether you see it as a Scrum story on a sprint board, a bar on a Gantt chart, a node in a CPM network, or a timer card on a field worker's phone — it is the same record. The view changes depending on your role. The data never duplicates.

Planning views PPT will provide

ViewBest forWhat it shows
Scrum boardAgile teams, sprintsStories in To Do / In Progress / Done, updated live from WorkHub
Sprint burndownSprint trackingRemaining story points vs days, actual hours vs estimate
CPM networkComplex installationsTask dependencies, critical path, float — built from PFE commissioning graph
Gantt chartTimeline planningTime-based bars with dependencies, resource assignments, baseline vs actual
Resource loadingCapacity managementWorker hours per week, overload warnings, rebalancing
Milestone roadmapClient communicationHigh-level milestones, complete only when WorkHub AND PFE both confirm

Definition of Done — dual confirmation

A task is truly Done in PPT only when two independent systems agree:

  • WorkHub confirms the work is finished — completion note, customer signature, time entry
  • The module confirms the physical reality changed — commissioning step advanced in the module's state machine, fault closed in PC-13, bus speed verified on the Domain Node

This dual confirmation means planning and physical reality are always in sync. A project cannot show 100% complete if the installation hardware is not actually commissioned. The planner sees the same ground truth as the field worker — because both are reading from the same modules.

PFE integration

PFE (SCLAN Programming and Field Environment) is the live editor and viewer for SCLAN installations. It is not a data store — each hardware module (Domain Node, SCLAN device) owns its own state machine (SME) in its own firmware, and each SaaS module owns its own database. PFE is the tool technicians and planners use to read and edit that distributed state in one place. WorkHub communicates directly with modules via API and webhooks — not through PFE. PFE is used in parallel, by humans, to inspect and configure the same installation that WorkHub tasks relate to.

How SCLAN modules create WorkHub tasks (via PFE-observable events)

WorkHub tasks are created automatically by module events — not by PFE itself. PFE can observe these events (they are visible in PFE Live Monitor), and a planner can also manually trigger tasks from PFE when they notice something. But the source of truth is always the module:

These tasks appear in WorkHub with full technical context in the description — segment ID, fault type, historical fault rate, firmware version — so the technician knows exactly what to investigate before arriving on site.

How WorkHub completion updates the modules (visible in PFE)

When you complete a task in WorkHub, the relevant modules are updated directly — these changes then become visible when a technician opens PFE:

  • Commissioning tasks — WorkHub calls the commissioning module API directly. The step advances in the module's state machine. A planner watching PFE sees the update because PFE is reading the module's live state.
  • Fault tasks — WorkHub calls the PC-13 API to close the fault record, and the Domain Node's ML fault counter is updated via the node's own API. PFE reflects this because it reads from the node live.
  • Hardware materials — materials logged in WorkHub are pushed to the installation inventory service. PFE can display this inventory because it reads from that service.
  • Field notes — completion notes are stored in WorkHub and surfaced in PFE's documentation view via a read API call.

Worker presence in PFE Live Monitor

When you start a timer on a task, WorkHub pushes a presence event to the installation's presence service. PFE Live Monitor reads this service — so a planner or manager with PFE open will see your name and task title on the installation. PFE is just the viewer for this — WorkHub wrote the data directly. When you stop the timer, the presence is cleared automatically.

What this means for the worker
When PFE sends you a task (e.g. a fault alert), the description already contains the segment ID, node ID, fault type, and technical context. You do not need to look anything up in PFE. Complete the task in WorkHub and the PFE record is automatically closed — no double-entry.

Commissioning workflow

For new SCLAN installations, the entire commissioning process runs through PFE and WorkHub together. The planner creates a commissioning project in PFE. Each step — cable survey, Domain Node mounting, bus termination, PnP discovery, context assignment, scene programming, client walkthrough — becomes a WorkHub task. As technicians complete each task, PFE advances the commissioning checklist. The final step — client sign-off — is the WorkHub completion certificate with the customer's signature. That signature closes the commissioning project in PFE and the installation is handed over.

Test avatar

WorkHub includes a built-in test system. Tap the ⚡ TEST button in the bottom-right corner of the app to open the test panel.

Running tests

Tap ▶ Run all to execute the full test suite (35 tests). Tests run in sequence and results appear in real time. The progress bar fills amber while running, then turns green (all pass) or red (failures).

Exporting results

  • 📋 — copies the full result report to the clipboard (Zwischenablage)
  • 💾 — downloads a .txt file named workhub_test_YYYY-MM-DD_HHMM.txt

What is tested

Data integrity, DOM structure, rendering, timer chain, report flow, materials, new task flow, language switching, desktop role views, mobile tabs, capacity calculation, and on-site context — 35 browser tests covering the full user journey.

Development rule
Any change to the app must pass both the static test suite (node test_workhub.js) and the in-browser test avatar before being deployed. The test avatar catches runtime DOM failures that the static tests cannot detect.
