The SCLAN silent guarantee — applicable to all five samples
Every interaction in these samples begins with an automated detection event — a fault threshold, a PnP discovery, a commissioning step becoming ready, an avatar change, an energy anomaly. In each case, no human noticed the problem first. The system noticed it, classified it, and acted on it.

This is the core value proposition of a SCLAN installation over any conventional building automation system: the building manages itself. Domain Nodes measure continuously (5×/second per segment). PC-13 builds fault profiles before faults become visible. The PFE avatar state machine watches security levels 24 hours a day. M-02 tracks energy at segment level, not building level.

In a conventional system, every one of these five workflows would have started with a human complaint — after a delay of hours, days, or weeks. In SCLAN, they start with a machine threshold — within seconds of the first measurable anomaly.

WorkHub is the interface that makes this machine intelligence actionable by field technicians — and transparent to customers. The technician gets a task with full context already written. The customer gets a completion certificate, a signature, and a delivery copy before they have finished explaining the problem they were about to report.

SCLAN SaaS — one planning truth, one execution reality
How WorkHub, PPT, PFE, and all modules form a single coherent system
The architectural principle
🎛 PFE — the spine
PFE is a live editor and viewer — not a data store. Each hardware module (Domain Node, SCLAN device) owns its own SME (State Machine Engine) stored in its own firmware. Each SaaS module owns its own database. PFE is the unified interface through which technicians read and edit that distributed state directly. Remove PFE and every module keeps running unchanged.
One truth — many views
A task is a task. Whether a planner sees it as a Gantt bar, a Scrum story on a sprint board, a CPM node on the critical path, or a field worker sees it as a timer card on their phone — it is the same object in the same database (WorkHub owns the task). PFE is a separate tool a technician uses in parallel to inspect and edit hardware module state — it does not mediate between modules. The view changes. The data ownership does not.

Why dual confirmation matters: In a conventional project management tool, "Done" means a human clicked a status button. In SCLAN, "Done" means two independent systems agree: the field worker confirmed the work is finished (WorkHub), and the SCLAN installation confirmed the physical reality changed (PFE). A commissioning step cannot be marked complete in PPT until a Domain Node has actually been discovered via PnP, configured in PFE, and confirmed active on the bus. Planning and physical reality are always in sync.
